# M1E — Authored Mechanisms Feature Train

> **Status:** Pass A (M1E.1 + M1E.2) implemented; automated verification passed, real-browser acceptance pending. Pass B (M1E.3 + M1E.4) remains unimplemented. Application version stays 0.9.3.

## Delivery boundaries and handoff

- **Pass A:** M1E.1 + M1E.2, authoring-map v8 and recording schema v24. See the [mechanism runtime contract](../notes/authored-mechanisms.md) for port names, exact clock timing, editor workflow, acceptance route, and implementation decisions.
- **Pass B:** M1E.3 + M1E.4, beginning only from a verified Pass A. Add controlled elevators, movers, and traps; retain current autonomous behavior and introduce any further replay boundary explicitly. Do not assume these devices exist yet.
- Acceptance map for Pass A: `maps/mechanisms.json`, opened with `?arena=mechanisms`. The integrated trap room described below belongs to Pass B.
- Resume checks: `git status --short`, this document, the mechanism contract, then focused tests and `npm run check`. The user-maintained Repomix is never regenerated by this train.

## Summary

Build a deterministic, declarative mechanism graph rather than a general event bus or scripting language. Human editors and future procedural generators will produce the same versioned map JSON; the compiler will validate named, typed ports and resolve stable authoring IDs into bounded
runtime arrays.

The train retains four scoped milestones, delivered in two implementation passes:

1. Signal-graph foundation with pressure plates and gates.
2. Levers, buttons, chains, logic devices, and complete wiring workflow.
3. Trigger-controlled elevators and moving blocks.
4. Bolt, spell, spike, and spear traps plus integrated hardening.

Each pass must leave a usable, replay-safe vertical slice. repomix-output.xml remains untouched.

## Core contracts and interfaces

### Authoring-map v8

Add one top-level section:

{
  "mechanisms": {
    "nextNodeOrdinal": 1,
    "nextLinkOrdinal": 1,
    "nodes": [
      {
        "id": "logic-0001",
        "definitionId": "logic.repeater",
        "properties": { "intervalTicks": 60 }
      }
    ],
    "links": [
      {
        "id": "wire-0001",
        "from": {
          "nodeId": "object.pressure-plate-0001",
          "port": "pressed"
        },
        "to": {
          "nodeId": "logic-0001",
          "port": "enabled"
        }
      }
    ]
  }
}

- Physical instances and connectors automatically become graph nodes when their catalog definition declares mechanism ports. Non-spatial logic devices live in mechanisms.nodes.
- Stable IDs are authoritative; runtime pool indices never appear in links.
- Links may cross layers and have no distance limit.
- Outputs may fan out. Each input accepts at most one link; authors use logic.any or logic.all for fan-in.
- Deleting an instance, connector, layer, or logic node removes incident links in the same undoable authoring command. Moving a device preserves links.
- v7 migration adds an empty mechanism section and preserves every existing behavior.
- Initial limits: 256 logic nodes, 512 total mechanism-capable nodes, and 1,024 links. Device limits are 128 controls, 128 gates, 64 movers, and 128 traps.
- Reject missing endpoints, unknown ports, pulse/level type mismatches, duplicate links, capacity overflow, invalid properties, and combinational cycles. A cycle is legal only when broken by an explicitly stateful node.
- Unwired ports are valid and produce warnings rather than preventing incremental map construction.

### Signals and fixed-tick behavior

Use two signal types:

- level: persistent boolean state, such as a held pressure plate.
- pulse: one-tick edge, such as a button strike or timer expiration.

Execution is synchronous and bounded:

1. At the beginning of tick N, consume source state and pulses collected during tick N−1.
2. Evaluate the compiled combinational DAG in stable node/link order.
3. Advance each stateful logic device exactly once.
4. Apply actuator requests before elevator motion, AI movement, and body physics.
5. During the remainder of tick N, collect pressure, interaction, projectile, arrival, and blocked transitions for tick N+1.

All pulses from one output during one tick coalesce into one pulse. No subscriber registration, dynamic dispatch, recursive delivery, or unbounded queue exists. Initialization/reset samples initial level sources and evaluates the graph before the first playable snapshot, without
generating edge pulses.

### Logic kit

Implement these non-spatial definitions:

- logic.not: one level input and one inverted level output.
- logic.all: two level inputs; true only when both are true.
- logic.any: two level inputs; true when either is true.
- logic.toggle: toggle/reset pulse inputs and an on level; reset wins if simultaneous.
- logic.latch: set/reset pulse inputs and an on level; reset wins if simultaneous.
- logic.delay: one pending pulse, delayed 1–216,000 ticks; configurable restart or ignore retrigger behavior.
- logic.timer: start/cancel pulses, active level, and elapsed pulse; start restarts and cancel wins.
- logic.repeater: enabled level and pulse output; fires immediately on enable, then every configured interval.
- logic.counter: pulse/reset inputs, saturating threshold 1–65,535, reached level and first-reach pulse; reset wins.

### Replay, commands, and diagnostics

- Advance recording/snapshot schema to v24 with profile authored-mechanisms-v1; pin graph/device capacities in the recording configuration.
- Schemas v2–v23 select profile none, retain their historical pressure-plate behavior, and never execute mechanism wiring.
- Add canonical interact: true as an edge-triggered fixed-tick command. Bind it to E; browser key repeat must not create repeated commands.
- Add detached snapshot/probe data for compiled counts, device states, logic state, dropped/overwritten diagnostics, and the latest 64 events. Provide __lantern.mechanisms() and __lantern.mechanismEvents().
- Keep a 256-entry diagnostic ring. Diagnostics never drive delivery.
- Reset reconstructs authored initial state. A mechanism-related editor mutation recompiles atomically, clears transient pulses, and restores the mechanism subsystem to authored initial state while leaving unrelated bodies intact; reject the edit if an initially solid actuator would
  overlap a live body.

- Do not bump the application/package version until a separate release checkpoint.

## Milestones within the two implementation passes

### M1E.1 — Graph foundation, pressure plates, and gates

Implement authoring-map v8, schema v24, graph compilation/evaluation, diagnostics, and one complete path from an existing pressure plate to a new mechanism.gate.

Pressure plates expose:

- pressed level.
- pressedEdge and releasedEdge pulses.
- Configurable activator categories: player, enemy, prop, and corpse; default to the existing player/enemy/prop behavior.
- Existing grounded support, full-footprint overlap, multi-plate contact, and no airborne/elevator-rider activation remain intact.

A gate is a one-cell solid/occluding instance:

- Input: open level.
- Outputs: isOpen level plus opened, closed, and blocked pulses.
- Closing retries while an actor, prop, or dynamic corpse overlaps its cell; it never entombs, teleports, or damages a body.
- State changes update runtime collision and occlusion overlays, increment the affected layer’s map revision, and invalidate relevant navigation/reachability caches without rewriting authored terrain.
- TrueSight and both renderers consume the runtime occlusion state.

Exit gate: a plate momentarily opens one or several gates; release closes them safely; reset, save/load, undo/redo, replay, and v7 migration are exact.

### M1E.2 — Controls, logic, and authoring workflow

Add physical controls:

- Floor lever: explicit player interaction toggles on; outputs on level and changed pulse.
- Wall pull-chain: explicit player interaction emits pulled; it ignores projectile impacts.
- Wall button: emits pressed on eligible body-contact entry or swept projectile impact. The projectile then completes its normal collision behavior, so a Fireball both presses the button and explodes at its face.
- Enemies cannot intentionally interact in this train, but that remains a later capability rather than being encoded as impossible.

interact resolves entirely in simulation authority:

- Same runtime layer, within 1.25 meters, clear grid line of sight, and inside a 120-degree facing cone.
- Select nearest eligible control, then stable authoring ID for exact ties.
- No eligible target is a deterministic no-op.

Introduce a wall-mounted placement rule for buttons, chains, emitters, and spears: the anchor must be a wall cell, rotation selects its outward face, and the adjacent front cell must be in bounds and non-solid.

Complete the author workflow:

- Add a Mechanisms channel and Wire tool.
- Clicking a source then a target creates a directed link; automatically choose ports only when exactly one compatible pair exists, otherwise require explicit port selection.
- Show directed wiring in edit mode, selected-device incoming/outgoing links, cross-floor endpoint badges, and structured catalog-driven property forms.
- Logic nodes are created and inspected in a graph list rather than stamped as invisible world objects.
- Preserve a collapsed advanced JSON property editor, but validate it through the same definition descriptors.
- Every placement, link, unlink, property edit, or cascade delete is one semantic undo/redo action.
- Procedural generation later emits the same v8 JSON; do not add a second generator-only API.

Exit gate: author a player-only lever, projectile button, and pull-chain puzzle using AND/OR, latch, timer, counter, delay, and repeater devices without hand-editing JSON.

### M1E.3 — Elevators and moving blocks

Extend each elevator connector with controlMode: "autonomous" | "triggered"; default and migrated maps remain autonomous.

Triggered elevators:

- Hold at initialStop until receiving callLower, callUpper, or cycle pulses.
- Preserve unstoppable in-flight travel.
- A request for the current destination is ignored; a request for the origin while moving banks one return trip.
- If both stop calls arrive together, a dwelling elevator chooses the opposite stop and a moving elevator banks its origin. Link order cannot change this result.
- Expose atLower/atUpper levels and arrivedLower/arrivedUpper pulses.
- Exclude triggered elevators from AI topology arcs until AI receives an explicit control-operating capability. Autonomous elevator navigation remains unchanged.

Add normal and spiked moving blocks:

- One-cell, same-layer, straight axis-aligned travel from authored point A for 1–16 cells, default speed 2 m/s with a validated 0.25–8 m/s range.
- positionB level sends the block toward B when true and A when false.
- Outputs: atA, atB, and blocked levels plus arrival/blocked edge pulses.
- Use bounded substeps and the existing collision solver to push actors and props.
- If a pushed body cannot escape fixed geometry, stop the mover for that substep and report blocked; never crush, teleport, or overlap.
- Update navigation occupancy only when the conservative discrete occupied-cell set changes, avoiding per-tick field rebuilds during sub-cell movement.
- Spiked blocks damage living actors for 25 points once per contact entry; props and corpses take no damage.

Exit gate: a plate or lever can call a controlled elevator, remove a gate, and drive a block that pushes the player down a corridor but safely stalls at an impossible pinch point.

### M1E.4 — Trap suite and integrated hardening

Add environmental ownership that damages any living team and grants no friendly immunity.

- Bolt emitter: wall-mounted, fires one neutral bolt projectile per pulse; default radius 0.06 m, speed 12 m/s, lifetime 4 seconds, and 15 direct damage. Bolts reuse the bounded projectile pool, swept collision, height checks, swap deletion, snapshots, and renderer path.
- Spell emitter: wall-mounted, references a registered spell ID and supports projectile or instant-impact mode. Initial support is Fireball only. Each activation derives its effect seed from simulation seed, stable emitter ID, and activation ordinal, and captures the active definition
  revision.

- Floor spikes: extended level, 12-tick rise and retract, non-blocking; deal 25 damage when reaching the active band or when an actor enters while extended, with a 30-tick per-source/target cooldown.
- Wall spear: thrust pulse, 8-tick extension, 6-tick hold, 8-tick retraction, 1.5-meter swept reach, and 25 damage once per actor per thrust. Pulses received while active are ignored and counted.
- Trap bolts can press wall buttons. Instant explosions, particles, and visual effects cannot emit mechanism signals.
- Repeat firing is authored with logic.repeater; traps themselves do not own hidden unlimited schedules.

Add a dedicated mechanism acceptance map containing:


- A weighted plate holding a gate open.
- A timed arrow room with a movable block used to stop the timer and unlock the exit.
- A projectile button activating a Fireball trap.
- A lever-controlled elevator.
- A moving block pushing actors toward spikes.
- Fan-out from one source and cross-layer wiring.

Exit gate: the acceptance map replays identically, saturates every declared pool predictably, and exposes enough diagnostics to explain every activation or refusal.

## Verification and acceptance

For every pass:

- Run focused authoring, graph, device, collision, renderer, replay, and migration tests, then npm run check.
- Assert stable ordering under reordered JSON input, fan-out, same-tick conflicts, pulse coalescing, exact timer boundaries, reset, undo/redo, atomic rejection, and all configured capacity limits.
- Keep genuine schema-v23 and authoring-map-v7 fixtures unchanged; add exact v24 replay and v7→v8 migration fixtures.
- Test wall-placement orientation, interaction range/LOS/facing/ties, Fireball and thrown-stone button strikes, chain projectile immunity, gate close blocking, controlled elevator banking, AI exclusion, mover tunneling/stall behavior, neutral trap damage, deterministic spell seeds, and
  swap-removal identity.

- Add a long mechanism soak combining repeaters, fan-out, elevators, movers, and projectile saturation; verify bounded work and deterministic hashes.
- Verify Canvas2D/Three.js parity, runtime occlusion, TrueSight concealment, and edit-only wiring visibility.
- Retain a real-browser Canvas2D and Three.js/WebGL or WebGPU pass as the final gate for control readability, gate/mover collision appearance, trap timing, wiring usability, and hidden-state leakage.

## Assumptions and explicit exclusions

- This is the planned M1E train; it does not mark M1D complete or silently reorder the roadmap.
- No embedded JavaScript, general scripting VM, dynamic subscriptions, arbitrary terrain/cell replacement, networking, ECS rewrite, or general 3D physics.
- Gates represent doors/removable walls without mutating authored cells. Stone/moss swaps and hole/support creation remain deferred.
- Existing elevators remain autonomous unless individually authored as triggered.
- Only the player intentionally uses levers and chains in v1.
- Environmental trap damage affects players and enemies; author-selectable faction filters are deferred.
- New spells may join spell emitters only after their handlers declare compatible emitter modes; this train does not invent additional spells.
- Balance values are centralized configuration, but the defaults above are the acceptance baseline.
