## Summary

Build a deterministic, declarative mechanism graph rather than a general event bus or scripting language. Human editors and future procedural generators will produce the same versioned map JSON; the compiler will validate named, typed ports and resolve stable authoring IDs into bounded
runtime arrays.

The train retains four scoped milestones, delivered in two implementation passes:

1. Signal-graph foundation with pressure plates and gates.
2. Levers, buttons, chains, logic devices, and complete wiring workflow.
3. Trigger-controlled elevators and moving blocks.
4. Bolt, spell, spike, and spear traps plus integrated hardening.

Each pass must leave a usable, replay-safe vertical slice. repomix-output.xml remains untouched.

## Core contracts and interfaces

### Authoring-map v8 — delivered Pass A boundary

Add one top-level section:

{
  "mechanisms": {
    "nextNodeOrdinal": 1,
    "nextLinkOrdinal": 1,
    "nodes": [
      {
        "id": "logic-0001",
        "definitionId": "logic.repeater",
        "properties": { "intervalTicks": 60 }
      }
    ],
    "links": [
      {
        "id": "wire-0001",
        "from": {
          "nodeId": "object.pressure-plate-0001",
          "port": "pressed"
        },
        "to": {
          "nodeId": "logic-0001",
          "port": "enabled"
        }
      }
    ]
  }
}

- Physical instances and connectors automatically become graph nodes when their catalog definition declares mechanism ports. Non-spatial logic devices live in mechanisms.nodes.
- Stable IDs are authoritative; runtime pool indices never appear in links.
- Links may cross layers and have no distance limit.
- Outputs may fan out. Each input accepts at most one link; authors use logic.any or logic.all for fan-in.
- Deleting an instance, connector, layer, or logic node removes incident links in the same undoable authoring command. Moving a device preserves links.
- v7 migration adds an empty mechanism section and preserves every existing behavior.
- Initial limits: 256 logic nodes, 512 total mechanism-capable nodes, and 1,024 links. Device limits are 128 controls, 128 gates, 64 movers, and 128 traps.
- Reject missing endpoints, unknown ports, pulse/level type mismatches, duplicate links, capacity overflow, invalid properties, and combinational cycles. A cycle is legal only when broken by an explicitly stateful node.
- Unwired ports are valid and produce warnings rather than preventing incremental map construction.

### Signals and fixed-tick behavior

Use two signal types:

- level: persistent boolean state, such as a held pressure plate.
- pulse: one-tick edge, such as a button strike or timer expiration.

Execution is synchronous and bounded:

1. At the beginning of tick N, consume source state and pulses collected during tick N−1.
2. Evaluate the compiled combinational DAG in stable node/link order.
3. Advance each stateful logic device exactly once.
4. Apply actuator requests before elevator motion, AI movement, and body physics.
5. During the remainder of tick N, collect pressure, interaction, projectile, arrival, and blocked transitions for tick N+1.

All pulses from one output during one tick coalesce into one pulse. No subscriber registration, dynamic dispatch, recursive delivery, or unbounded queue exists. Initialization/reset samples initial level sources and evaluates the graph before the first playable snapshot, without
generating edge pulses.

### Logic kit

Implement these non-spatial definitions:

- logic.not: one level input and one inverted level output.
- logic.all: two level inputs; true only when both are true.
- logic.any: two level inputs; true when either is true.
- logic.toggle: toggle/reset pulse inputs and an on level; reset wins if simultaneous.
- logic.latch: set/reset pulse inputs and an on level; reset wins if simultaneous.
- logic.delay: one pending pulse, delayed 1–216,000 ticks; configurable restart or ignore retrigger behavior.
- logic.timer: start/cancel pulses, active level, and elapsed pulse; start restarts and cancel wins.
- logic.repeater: enabled level and pulse output; fires immediately on enable, then every configured interval.
- logic.counter: pulse/reset inputs, saturating threshold 1–65,535, reached level and first-reach pulse; reset wins.

## Milestones within the two implementation passes

### M1E.1 — Graph foundation, pressure plates, and gates

Implement authoring-map v8, schema v24, graph compilation/evaluation, diagnostics, and one complete path from an existing pressure plate to a new mechanism.gate.

Pressure plates expose:

- pressed level.
- pressedEdge and releasedEdge pulses.
- Configurable activator categories: player, enemy, prop, and corpse; default to the existing player/enemy/prop behavior.
- Existing grounded support, full-footprint overlap, multi-plate contact, and no airborne/elevator-rider activation remain intact.

A gate is a one-cell solid/occluding instance:

- Input: open level.
- Outputs: isOpen level plus opened, closed, and blocked pulses.
- Closing retries while an actor, prop, or dynamic corpse overlaps its cell; it never entombs, teleports, or damages a body.
- State changes update runtime collision and occlusion overlays, increment the affected layer’s map revision, and invalidate relevant navigation/reachability caches without rewriting authored terrain.
- TrueSight and both renderers consume the runtime occlusion state.

Exit gate: a plate momentarily opens one or several gates; release closes them safely; reset, save/load, undo/redo, replay, and v7 migration are exact.

### M1E.2 — Controls, logic, and authoring workflow

Add physical controls:

- Floor lever: explicit player interaction toggles on; outputs on level and changed pulse.
- Wall pull-chain: explicit player interaction emits pulled; it ignores projectile impacts.
- Wall button: emits pressed on eligible body-contact entry or swept projectile impact. The projectile then completes its normal collision behavior, so a Fireball both presses the button and explodes at its face.
- Enemies cannot intentionally interact in this train, but that remains a later capability rather than being encoded as impossible.

interact resolves entirely in simulation authority:

- Same runtime layer, within 1.25 meters, clear grid line of sight, and inside a 120-degree facing cone.
- Select nearest eligible control, then stable authoring ID for exact ties.
- No eligible target is a deterministic no-op.

Introduce a wall-mounted placement rule for buttons, chains, emitters, and spears: the anchor must be a wall cell, rotation selects its outward face, and the adjacent front cell must be in bounds and non-solid.

Complete the author workflow:

- Add a Mechanisms channel and Wire tool.
- Clicking a source then a target creates a directed link; automatically choose ports only when exactly one compatible pair exists, otherwise require explicit port selection.
- Show directed wiring in edit mode, selected-device incoming/outgoing links, cross-floor endpoint badges, and structured catalog-driven property forms.
- Logic nodes are created and inspected in a graph list rather than stamped as invisible world objects.
- Preserve a collapsed advanced JSON property editor, but validate it through the same definition descriptors.
- Every placement, link, unlink, property edit, or cascade delete is one semantic undo/redo action.
- Procedural generation later emits the same v8 JSON; do not add a second generator-only API.

Exit gate: author a player-only lever, projectile button, and pull-chain puzzle using AND/OR, latch, timer, counter, delay, and repeater devices without hand-editing JSON.

### M1E.3 — Elevators and moving blocks

Extend each elevator connector with controlMode: "autonomous" | "triggered"; default and migrated maps remain autonomous.

Triggered elevators:

- Hold at initialStop until receiving callLower, callUpper, or cycle pulses.
- Preserve unstoppable in-flight travel.
- A request for the current destination is ignored; a request for the origin while moving banks one return trip.
- If both stop calls arrive together, a dwelling elevator chooses the opposite stop and a moving elevator banks its origin. Link order cannot change this result.
- Expose atLower/atUpper levels and arrivedLower/arrivedUpper pulses.
- Exclude triggered elevators from AI topology arcs until AI receives an explicit control-operating capability. Autonomous elevator navigation remains unchanged.

Add normal and spiked moving blocks:

- One-cell, same-layer, straight axis-aligned travel from authored point A for 1–16 cells, default speed 2 m/s with a validated 0.25–8 m/s range.
- positionB level sends the block toward B when true and A when false.
- Outputs: atA, atB, and blocked levels plus arrival/blocked edge pulses.
- Use bounded substeps and the existing collision solver to push actors and props.
- If a pushed body cannot escape fixed geometry, stop the mover for that substep and report blocked; never crush, teleport, or overlap.
- Update navigation occupancy only when the conservative discrete occupied-cell set changes, avoiding per-tick field rebuilds during sub-cell movement.
- Spiked blocks damage living actors for 25 points once per contact entry; props and corpses take no damage.

Exit gate: a plate or lever can call a controlled elevator, remove a gate, and drive a block that pushes the player down a corridor but safely stalls at an impossible pinch point.

### M1E.4 — Trap suite and integrated hardening

Add environmental ownership that damages any living team and grants no friendly immunity.

- Bolt emitter: wall-mounted, fires one neutral bolt projectile per pulse; default radius 0.06 m, speed 12 m/s, lifetime 4 seconds, and 15 direct damage. Bolts reuse the bounded projectile pool, swept collision, height checks, swap deletion, snapshots, and renderer path.
- Spell emitter: wall-mounted, references a registered spell ID and supports projectile or instant-impact mode. Initial support is Fireball only. Each activation derives its effect seed from simulation seed, stable emitter ID, and activation ordinal, and captures the active definition
  revision.

- Floor spikes: extended level, 12-tick rise and retract, non-blocking; deal 25 damage when reaching the active band or when an actor enters while extended, with a 30-tick per-source/target cooldown.
- Wall spear: thrust pulse, 8-tick extension, 6-tick hold, 8-tick retraction, 1.5-meter swept reach, and 25 damage once per actor per thrust. Pulses received while active are ignored and counted.
- Trap bolts can press wall buttons. Instant explosions, particles, and visual effects cannot emit mechanism signals.
- Repeat firing is authored with logic.repeater; traps themselves do not own hidden unlimited schedules.

Add a dedicated mechanism acceptance map containing:


- A weighted plate holding a gate open.
- A timed arrow room with a movable block used to stop the timer and unlock the exit.
- A projectile button activating a Fireball trap.
- A lever-controlled elevator.
- A moving block pushing actors toward spikes.
- Fan-out from one source and cross-layer wiring.

Exit gate: the acceptance map replays identically, saturates every declared pool predictably, and exposes enough diagnostics to explain every activation or refusal.

### B3. Controlled elevator vertical slice

Implement and test this before movers. It is the smallest complete Pass B slice.

1. Thread `controlMode` through normalized authoring, commands/history, compiler,
   scenario recipes, pool spawn, snapshots/probes and connector inspector.
   Add/copy/reset any new typed-array columns in `ElevatorPool.removeSwap`.
2. Adapt a triggered connector into **one** graph node with the connector ID,
   definition ID and both layer IDs. Do not fabricate duplicate lower/upper
   instance IDs. Resolve runtime lift by stable authoring ID, never saved pool
   index. Check ID collisions between connector, instance and logic namespaces.
3. Preserve autonomous `step/request/cycle` behavior under historical profiles.
   For triggered lifts, idle is genuinely idle: no pending request means no
   departure, including at dwell zero. Use an explicit one-slot pending return
   request, separate in meaning from current destination.
4. Read all three input pulses once per lift before deciding a request. Apply
   the following arbitration; do not invoke request sequentially per link.

| Inputs/state | Chosen behavior |
| --- | --- |
| Idle, no pulse | Hold current stop indefinitely. |
| Idle, one explicit stop call | Current stop is a no-op; opposite stop departs on this tick, bypassing remaining idle dwell like current debug `request`. |
| Idle, both stop calls | Choose opposite stop. |
| Idle, cycle only | Choose opposite stop explicitly. |
| Moving, call destination | Ignore; do not clear a previously banked return. |
| Moving, call origin / both calls / cycle only | Bank exactly one return to origin; never reverse in flight. Repetition cannot build a queue. |
| Explicit stop call(s) and cycle together | Explicit stop call arbitration wins. |
| Arrival with banked return | Finish travel, publish arrival, honor the authored dwell, then depart once; otherwise remain idle. |

5. Treat diagnostic lift actions applied earlier in the same tick as provisional;
   a graph stop request wins for a triggered lift. Document this precedence and
   leave autonomous debug-command semantics unchanged.
6. Initialize endpoint levels without pulses. After `elevators.step(dt)`, derive
   endpoint levels from actual dwelling state/stop, not requested destination.
   Both are false in flight. Arrival pulses are collected for the next graph
   tick, exactly once. A same-tick request and arrival use pre-step motion state.
7. In `compileNavigationTopology`, retain ports and approach links, omit the two
   triggered travel arcs. Skeleton generation may create approaches but must
   not promise automatic inter-floor travel. Already-present bodies can still
   physically ride; exclusion is AI route planning, not a new boarding ban.
8. Extend wire picking to connector endpoints on either floor; display local
   endpoint position/floor badges while keeping one node identity. Panel edits
   must dispatch `updateConnector`, not `updateInstanceProperties` or logic
   deletion. Keep ordinary connector tools/palette behavior intact when adding
   mechanism metadata to the connector catalog definition.

Checkpoint: autonomous golden fixture unchanged; idle triggered lift remains
idle for 600 ticks; all conflict/return cases, occupied edit rejection, reset
in transit, pool swap removal, two-floor wiring and AI exclusion pass.

### B4. Movers: bounded kinematic bodies, not heavy rocks or moving grid walls

**Highest-risk slice. Prove its push/stall contract before adding spike damage.**
Do not fake a mover as an extremely massive `RockPool` body: explosions and the
ordinary impulse solver must never move it off its authored rail.

Data and placement:

- Proposed **new** `src/sim/mechanism_mover_pool.js` owns at most 64 immutable
  rail recipes and SoA current/previous X/Z, progress, target, blocked state,
  stable runtime/authoring identity and layer. It needs no general gravity,
  passenger/support ownership, rotation dynamics, or public command API.
- A is the authored cell center. B = A + rotated unit direction × distanceCells.
  Collision footprint is a one-meter axis-aligned square; planned height is
  1.9m, floor-anchored at layer baseY. A mover is not a walkable support.
  Initial physical position is A even when initial graph `positionB` is true;
  movement starts on the first tick, never teleports during graph initialization.
- Validate the entire swept lane, not only A/B, on create, move, rotate,
  property update, resize and terrain edit. Reject out-of-bounds, fixed solids,
  elevator apertures/endpoints, holes and breakaway floors. This deliberately
  excludes moving platforms and rails over gaps. Dynamic clutter may occupy
  the lane; safe runtime pushes handle it. Gates may intersect a lane and then
  act as runtime blockers. Intersecting mover lanes are legal but movers never
  push one another; stable-ID arbitration and blocking keep the result bounded.
- Plates and non-blocking spikes may lie along the lane. Allow the specific
  mover/plate or mover/spikes initial-footprint combination where needed;
  do not globally disable instance-overlap validation. Mover initial A must
  not overlap another solid or authored actor/prop; live edits have an additional
  current-body guard. Placement previews must receive properties to validate B.
- `compileLayer` must exclude mover solidity from the fixed collision bake,
  yet still validate its initial footprint and provide runtime/editor recipes.
  Static topology costs describe potential routes with movable blockers absent,
  as Pass A already does for gates. Do not erase authored terrain underneath A.

Motion integration and transaction:

1. Latch `positionB` after graph evaluation. A change mid-travel reverses desired
   rail direction on the next physics step; clamp arrival exactly to A/B.
   Preserve tick-start previous poses for interpolation.
2. Integrate mover contact into `#bodyPhysicsSystem` substeps, after ordinary
   body integration with stationary-mover contacts included in solver passes.
   Include mover speed in the substep calculation and require mover displacement
   <=0.025m per substep (8m/s at 60Hz needs at most six). Keep the total cap at
   eight and record budget refusal rather than performing unchecked motion.
3. For each mover in stable authoring-ID order, attempt one rail displacement
   in reusable scratch storage. Build a bounded push closure using existing
   circle/box footprint contacts, stable body kind + stable ID, and layer/height
   overlap. Displace contacted bodies along the rail by only the required
   separation, propagate to bodies they touch, and validate against fixed grid,
   closed gates, other movers and lift shaft/deck blockers. No unbounded recursion.
4. Cap propagation by the live-body capacity, with at most four bounded contact
   relaxation passes. Check the final scratch state for residual penetration
   beyond configured physics slop. If the closure cannot fit or budget expires,
   discard the entire candidate: mover and pushed bodies retain pre-attempt
   state, report blocked. This is a safe conservative stall, not a promise to
   solve arbitrary packing or find a path around a corner.
5. Commit only a valid candidate. Scratch must cover every field it changes
   (positions, velocity channels and touch state); avoid invoking live damage,
   contact-log or sound functions before commit. Do not roll back earlier
   independent ordinary movement or another mover's accepted transaction.
6. Reuse `dynamic_body_velocity.js` channel ownership for physical contacts:
   controller pressure against a stopped mover must not accumulate external
   recoil. Do not repeatedly add mover velocity as an impulse or integrate a
   committed displacement a second time. Rebuild/query broadphase after accepted
   body displacements before subsequent contact consumers.
7. Stationary movers must also block ordinary body motion, projectiles and gate
   closure; a path-drive-only overlap test is insufficient. Apply the same
   collider to airborne/falling actors whose vertical interval overlaps it.
   No new support kind is introduced. Final body checks run before pressure
   plates and contact hazards sample the committed positions.

Keep pure contact/transaction helpers in a proposed **new**
`src/sim/kinematic_mover.js`; retain simulation authority and existing body pools
in `Simulation`. Prefer allocation-free scratch adapters to exporting private
simulation internals or rewriting the entire collision engine.

Derived state and sources:

- AtA/atB are exact endpoint levels. `blocked` means a requested displacement
  was refused during this tick; clear when motion succeeds or no motion is
  requested. `blockedEdge` emits on false→true only. Endpoint arrival pulses
  emit only when motion actually reaches a new endpoint, never on reset.
- Treat movers as `prop` activators for plate filters, using their real current
  square footprint and floor anchoring. Existing `#forMechanismBodies` and
  `#bodyPressesPlate` do not know this pool; add a separate bounded adapter rather
  than passing a new kind into a helper that assumes RockPool columns.
- Spiked movers share identical collision. Deal 25 damage once on contact entry
  to a live player/enemy, with a bounded per-source target-identity table. Contact
  at a safely stalled face still counts; separation permits another entry.
  Do not damage props/corpses or add crushing damage.

Checkpoint tests: A/B reversal and endpoint clamp; max-speed thin-body contact;
circle and rotated fixed-box props; player→prop→wall push chain; dynamic corpse;
two opposing movers; gate closing onto a mover; no residual overlap or stored
recoil; budget stall rollback; different-floor and overhead bodies; plate
activation; reset/live edit at A with a body now occupying A.

### B5. Separate exact collision from conservative navigation/occlusion

Do **not** paint every mover-touched cell into `layerMaps`: existing body grid
resolvers would push actors against a staircase-shaped wall and the renderer
could draw static walls on top of the moving block.

- Keep fixed/gate/destruction collision maps as the ordinary physics base;
  movers add exact AABB contacts. Maintain separate composed navigation maps
  for current fixed blockers plus conservative mover cell occupancy. With
  axis-aligned one-cell travel a mover overlaps at most two cells at once;
  boundary tangency alone is not occupancy. Cache each mover's cell set.
- Maintain per-cell mover reference counts or rebuild the affected layer's
  bounded mover mask on changes. When one mover leaves, never clear another
  mover, closed gate or fixed wall. Use the same composition principle for
  destruction and live editor rebuilds; don't blindly restore “cell = 0”.
- Refresh navigation revisions/caches only when a cell set or another blocker
  changes, not for every fractional X/Z update. Batch per-layer invalidation.
  Audit `#navigationSystem`, topology movement, destination-field requests,
  gradient steps, reachability and cache resets for their map/revision inputs.
  Old-profile paths continue using their original maps and scheduling.
- Snapshot `map.cells` remains fixed/gate geometry; overlay conservative mover
  occlusion into `occluderCells` with the appropriate visible-layer revision.
  TrueSight consumes that mask. Authoritative perception/LOS and explosion
  obstruction must also see movers through an explicit composed blocker view;
  changing only renderer visibility would leave AI seeing through them.
- Audit `gridRayBlocked`/visual checks, spawn/reachability tests, projectile
  obstacle tests and debug probes for the intended view. Document each view's
  purpose rather than replacing `this.map` globally. Particle bounce against
  moving blocks is presentation polish, not required gameplay authority; it
  must not become a mechanism event source.
- Conservative full-cell moving occlusion is the accepted Pass B limit. No
  hinged-door peeking, sub-cell TrueSight redesign, wall-mesh rebuild per tick,
  or camera/range refactor is hidden inside this work.

Checkpoint: mover crossing a cell boundary changes occupancy/revision once;
fractional travel within the same set does not churn destination fields; gates,
destroyed obelisks and multiple movers compose; reset removes all stale masks;
both gameplay sight and presented concealment follow the correct runtime floor.

- Extend actor candidate selection in `#projectileSystem` to include player

  and stable-ID ties; keep historical player/enemy behavior behind its profile.
  A neutral enum alone currently skips both branches and hits no actors.
- Reuse the 256-slot projectile pool; add `bolt` kind, fixed 0.9m launch offset,
  radius 0.06, speed 12, lifetime 4s, damage 15 in central configuration. Do not

- Sweep against grid/gates, exact movers, lift height volumes, props, corpses,
  player and enemies. New environmental shots use a vertical interval test

  historical actor-hit semantics. Match corpse height to its existing physical

- Spawn outside the mounting wall: `wallFace` is only 0.001m outside the wall

- Call `#damagePlayer`/`#damageEnemy`, never write health directly. Include stable

- Audit `#selectVisibleHostileProjectile` and projectile dodge selection: both

- Full pool: drop this pulse, increment projectile dropped plus per-emitter

  emitters in stable-ID order. Existing player/enemy casts keep their current

  This makes same-tick capacity priority explicit and testable.

### B8. Spikes, spears and bounded target memory

Proposed **new** `src/sim/mechanism_traps.js` owns bounded phase/progress and
source-local activation/cooldown state for at most 128 traps. It receives
simulation-owned queries/damage adapters; it does not import renderer or DOM.
Spiked-mover contact memory uses the same identity rules, but the 64 mover limit.

Choose these concrete timing rules for the first implementation:

- **Floor spikes:** integer extension progress 0..12, changes by one per tick
  toward current `extended` request. Reversing the level reverses smoothly from
  current progress. Planned active band is progress >=6; planned maximum height
  is 0.8m, rising proportionally to progress. Render that same progress.
  A transition into the active band or a live actor entering the active volume
  is a damage candidate; apply 25 only if that source/target's 30-tick cooldown
  has elapsed. Remaining motionless on raised spikes does **not** create periodic
  damage every 30 ticks. A rejected entry during cooldown does not become a
  delayed hit just because time later passes; a new entry/activation is needed.
- **Wall spear:** accepted thrust starts an 8-tick extension, 6-tick hold,
  8-tick retraction. Acceptance tick is extension step 1, ticks 1..8 extend,
  9..14 hold, 15..22 retract; tick 23 can accept a new thrust. Ignore/count all
  pulses while active, including on tick 22. Maximum reach 1.5m from wall face,
  planned collision radius 0.08m, world-Y center baseY+0.9m. Sweep the actual
  previous→current reach so thin/fast-crossing actors are not skipped.
- Spear reach is clipped by walls/gates, exact movers, props/corpses and lift
  geometry at that height. Actors do not shorten it: each intersected living
  actor takes 25 at most once per thrust, including entering during hold or
  retraction. It creates no actor/prop push and no walk-blocking grid cell.
  No hits through a wall just because the configured reach extends beyond it.
- Floor spikes use actual X/Z footprint plus world-Y overlap; not just layer
  equality. Jumping clear is possible; overhead elevator passengers and adjacent
  floors are not hit. They do not block movement or become supports/occluders.
- Evaluate hazard contact after final body/vertical motion, before projectile
  processing and dead-enemy transfer. Include swept body movement for crossing
  the thin spear/spike volume. Collect bounded contact candidates over committed
  substep segments, not an unbounded path log or a start-to-end chord that cuts
  through corners the actor never crossed. Record damage only for accepted physical movement,
  never a rolled-back mover candidate. Initial/reset snapshot generates no damage;
  subsequent active-band entry can damage on a real tick.

Target memory must be bounded without silently evicting live cooldown entries:

- Preallocate per-source/per-actor-slot arrays sized from player + configured
  enemy capacity; store/check stable actor ID (and spawn identity where needed)
  alongside entry/last-damage/thrust stamps. Copy/remap columns when EnemyPool
  swap-removes, clear reused slots, reset on subsystem rebuild. An alternative
  stable-ID table is acceptable only with an explicit equal bound and no loss of
  required live-target memory. Never use an ever-growing `Set` of historical IDs.
- Compute worst-case memory from 128 traps + 64 spiked movers and configured
  actors before allocation. Publish capacity/work counters and pin any new
  limits in v25. Corpse conversion ends living-target eligibility immediately;
  inert decorative corpses need no contact table.
- Reuse the 256-entry mechanism diagnostic ring for activation, ignored-busy,
  blocked-muzzle, blocked-push, pool-full and budget-stall reasons. Expose bounded
  cumulative counters plus latest events; never enqueue unlimited pending shots.
