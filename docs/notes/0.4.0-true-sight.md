# Lantern 0.4.0 TrueSight Visibility and Shroud

> **Authority:** local presentation and interaction only
>
> **Compatibility:** simulation truth, schema v4, scenario v2, map v1, command recordings, replay, physics, AI, casting, collision, and the frozen particle profiles are unchanged

## Observer contract

TrueSight is current line of sight only. It is player-centered, 360 degrees,
map-bounded, and has no distance cutoff or explored-memory layer. The
interpolated player X/Z position is the observer; camera position and zoom do
not affect visibility. In 0.4.0 only solid wall cells block sight.

The renderer-independent system lives under `src/visibility/`. It hashes the
map, rebuilds topology only after a real topology change, extracts and merges
exposed floor/wall edges, and uses their deduplicated endpoints plus all map
corners as angular boundaries. Each boundary receives a center ray and
`±1e-7` radian neighbors. Rays traverse the grid deterministically until the
first solid cell or map exit.

Exact grid-corner ties advance both axes and select the lowest solid-cell index.
Every traversal is bounded by `map.width + map.height + 4` crossings. A frame
uses at most 2,048 rays; excessive corner topology switches to 2,048 evenly
spaced deterministic rays. Sorted intersections remove points within
`1e-5m` and redundant collinear vertices.

This follows Nox's angular-boundary behavior without copying its legacy
implementation. See the
[OpenNox sight implementation](https://github.com/noxworld-dev/opennox/blob/0e78e4cd5be47c9ab34d85110f1ae21bafbfb217/src/client/sight.go).

## Masks and fading

Each `TrueSightFrame` exposes:

- the current origin, polygon, debug rays, hit walls, and visible walls;
- reusable hard logical and fading display `Uint8Array` masks;
- `isPointVisible(x, z)` and center-plus-eight-sample
  `isCircleVisible(x, z, radius)` lookups;
- JSON-safe counts, dimensions, flags, snap reason, and cached timing
  summaries.

The raster target is eight texels per meter, reduced uniformly so neither
dimension exceeds 256. The standard 24m square arena is `192×192`. A visible
floor region touching an exposed edge marks the complete obstructing wall cell
visible; another wall behind it remains hidden.

Reveal approaches the hard target in 100 ms and conceal in 150 ms. Setting
`sightFade=0` copies the target immediately. First frame, reset, map change,
tick rollback, movement jump over two meters, renderer recovery request, and
entering or leaving edit mode also snap immediately. Polygon, ray, wall, and
mask storage is reused during steady-state updates.

## Presentation and local interaction

One shared `PresentationFlags` instance owns lighting, TrueSight, fade, and
debug switches. The fixed-frame presentation order is:

1. update TrueSight from the snapshot and interpolation alpha;
2. gate hover and the resolved pinned presentation with the logical mask;
3. render with the shared frame;
4. collect presentation and TrueSight diagnostics.

A hidden cursor returns no hover target. A hidden pinned entity retains its
stable identity but exposes no marker, position, velocity, or inspector JSON
until visible again. The unrestricted `window.__lantern.queryAt` diagnostic
does not change. Edit mode reveals the full map and every entity immediately.
Casting and all simulation behavior continue through hidden space.

Canvas2D draws its ordinary frame and then stretches the display mask over the
map from a reusable offscreen canvas. Sight debug draws hit-wall cells, rays,
and the polygon above the shroud.

The Three.js route keeps resident `MeshStandardNodeMaterial`,
`MeshBasicNodeMaterial`, and `LineBasicNodeMaterial` pipelines. One unsigned
byte, red-format, linearly filtered, clamp-to-edge `DataTexture` samples
world-X/Z coordinates through TSL `positionWorld`. The display node drives
opacity, discard, alpha hashing, alpha-to-coverage when AA starts enabled, and
the shadow mask. Floor, grid, walls, player, rocks, fireballs, particles,
markers, and editor previews use the same node. This masks emissive fire
geometry before bloom.

Point-light leases and resident slots do not change when hidden. Their
assignment intensity is multiplied by display visibility at the assignment's
X/Z point, so the light fades with its carrier and returns without hopping.
TSL material-node behavior is documented in the
[Three.js TSL guide](https://threejs.org/docs/TSL.html).

## URL flags, probes, and reports

The live, URL-only flags are:

| Setting | Default | Effect |
| --- | ---: | --- |
| `trueSight` | `1` | Use current LOS; `0` reveals the map |
| `sightFade` | `1` | Use 100/150 ms transitions; `0` snaps |
| `sightDebug` | `0` | Draw visibility diagnostics |

`window.__lantern.trueSight()` returns the current JSON-safe frame diagnostic.
`window.__lantern.isVisible(x, z, radius = 0)` queries the hard mask.
Render Lab includes the flags, mask/geometry counts, and `trueSightCpuMs`.

Performance reports are format v2. In addition to the 0.3.3 data they record
maximum rays, polygon vertices, visible walls, mask width/height, and separate
TrueSight timing percentiles. Resetting performance metrics clears this timing
history with the existing runtime and presentation histories.

## Validation contract

Automated coverage includes empty and occluded maps, angular wedge width,
front/behind walls, doorways and concave corridors, diagonal ties, grid-line
origins, topology invalidation, deterministic fallback, mask caps, fade and
snap policy, partial circle peeking, local interaction gating, stable hidden
light leases, report v2 shape, snapshot immutability, and a sustained
storage-reuse soak.

Release browser acceptance still requires Canvas2D, automatic WebGPU, forced
WebGL 2, and LAN-phone WebGL 2 checks. Walk around isolated walls, doorways,
and concave corners; cast through hidden space; verify mesh, spark, light, and
bloom conceal together; toggle all three flags; and verify edit/play snapping.
Low and Balanced captures retain the existing presentation CPU p99 target of
8 ms while reporting TrueSight separately.

Deferred work includes exploration memory, multiple observers, ranges,
windows, height-aware sight, front-wall camera transparency, sound perception,
and server-enforced multiplayer concealment.
