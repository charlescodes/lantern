# Lantern 0.8.2 Player-Follow Camera

## Contract and release boundary

Lantern 0.8.2 makes the main player the permanent play-camera target in both
Canvas2D and Three.js. The application, package, and UI version advance to
0.8.2. Snapshot and recording schema v8, scenario v3, map v1, Fireball
definition v1, performance-report v2, simulation behavior, commands, and replay
compatibility remain unchanged.

This is a presentation and local-input release. Camera state is neither
authoritative nor serialized, and this release introduces no networking model.

## Exact play-camera attachment

At the beginning of every play-mode render, the camera target resolves from the
same local fixed-tick pose used to draw the player:

`rendered = previous + (current - previous) * alpha`

The bounded runtime alpha is local presentation timing, not network
interpolation. The camera adds no spring, damping, dead zone, look-ahead,
prediction, or persistent offset. This keeps the player's ground anchor fixed
at the viewport center while the world moves smoothly at the display cadence.
The rule remains active while play is running, manually paused, defeated,
resetting, or restarting.

## Input and editor behavior

The stored pointer is reprojected through the camera after every automatic
focus or zoom change and before held-RMB movement commands are sampled. Cursor
markers, visibility gating, casts, selection, inspection, and editor tools
therefore continue to refer to the ground point beneath the visible pointer as
the camera moves.

Wheel zoom in play changes metric coverage around the player without changing
the camera target. MMB panning is ignored in play. Edit mode remains paused and
free: MMB pans in world meters, wheel zoom stays cursor-anchored, and Focus/F
recenters on the displayed player pose. Returning to play reattaches the camera
before the next command or rendered frame.

## Verification boundary

Automated coverage locks render-alpha position resolution, exact Canvas2D and
Three.js camera targets, play/edit ownership, centered and cursor-anchored zoom,
play pan suppression, edit panning, and pointer reprojection. Existing syntax,
simulation, replay, soak, and presentation tests remain the regression suite.

Final acceptance requires real-browser play on Canvas2D, automatic 3D, and
forced WebGL 2. Sustained movement must leave the player ground anchor visually
stationary while the world scrolls smoothly; targeting must remain under the
pointer; edit mode must detach and reattach without a stray play frame. These
perceptual and real-GPU checks cannot be certified by Node tests alone.
