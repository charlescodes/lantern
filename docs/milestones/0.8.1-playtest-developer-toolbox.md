# Lantern 0.8.1 Playtest Mode and Developer Toolbox

## Contract and release boundary

Lantern 0.8.1 makes ordinary playtesting the default browser experience. The
application/package/UI version advances to 0.8.1, while snapshot and recording
schema v8, scenario v3, map v1, Fireball definition v1, performance-report v2,
simulation behavior, capacities, command ordering, and replay compatibility all
remain unchanged.

This is a presentation and local-input release. Toggling the toolbox never
injects a fixed-tick command and is not serialized.

## Clean playtest boot

The document boots with `data-mode="play"` and
`data-developer-tools="closed"`. In this state the arena occupies the complete
viewport. The following developer surfaces are absent from layout, hit testing,
keyboard focus, and the accessibility tree:

- the top simulation/edit/focus toolbar and run summary;
- Spell Lab, AI View, and Render Lab windows and launchers;
- the right-side frame, pool, inspector, debug, event, and artifact instruments;
- the bottom pointer/controls rail, corner readout, and authoring palette;
- AI View drawing plus coordinate labels, velocity vectors, particle height
  stems, contact markers, blast-force diagrams, selection inspection, and
  TrueSight diagnostic geometry.

The defeat overlay and ordinary play cursor remain available. Clean mode
suppresses diagnostic drawing at presentation time without changing the
authoritative debug/configuration flags. In particular, recorded ground-bounce
and spark-wall-collision behavior continues exactly as configured.

## Semicolon gate

Pressing the unshifted semicolon key toggles the complete developer toolbox.
The shortcut is ignored while typing in an input, textarea, select, or editable
element. A held key does not repeatedly toggle the toolbox. Opening restores
each developer surface and its existing local state, then requests a renderer
layout refresh for the resized canvas.

Space, period, R, Shift+R, E, and F are developer shortcuts and act only while
the toolbox is open. Mouse movement, casting, camera zoom, and camera pan remain
available in clean playtest mode. Hover inspection and stable-ID pinning are
also toolbox-only so an ordinary cast click cannot leave a hidden diagnostic
selection.

Closing the toolbox closes Render Lab, returns an active scenario editor to
play mode through its existing pause/resume path, and focuses the arena. A
manually paused play session remains paused; reopening the toolbox exposes its
status and Resume control.

## Parked authoring windows

Spell Lab starts closed with a launcher in the toolbox. **Collapse** now removes
the panel from the arena instead of leaving a minimized heading over gameplay;
the launcher reappears in the toolbox. Its draft, validation, applied revision,
seed lock, and last-target state remain in memory. AI View and Render Lab retain
their established read-only/presentation contracts behind the same outer gate.
The non-authoritative direction for applying this launcher-to-window lifecycle
to other qualifying tools is recorded as
[LT-002: Parkable developer windows](../soft-specs/long-term-improvements.md#lt-002-parkable-developer-windows).

## Verification boundary

Automated coverage locks the clean boot attribute, the single developer-surface
CSS gate, full-viewport layout, semicolon recognition, inert/accessibility state
restoration, parked Spell Lab markup, input-shortcut gate, and presentation-only
diagnostic gate. Existing unit, deterministic replay, soak, Canvas2D, and Three.js
tests remain the regression suite. Final visual fit, keyboard feel, and ordinary
playtest acceptance still require a real browser on the target machine.
