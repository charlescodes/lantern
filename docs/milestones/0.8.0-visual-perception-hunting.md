# Lantern 0.8.0 Visual Perception and Hunting

## Contract and release boundary

Lantern 0.8.0 replaces the live omniscient tactical enemy with
`perceptive-wizard-v1` and advances application/package/UI plus snapshot and
command-recording schema to v8. Scenario v3, map v1, Fireball definition v1,
performance-report v2, combat rules, and the default four-alive encounter
cadence remain unchanged.

Replay behavior is selected by the recording schema and stays frozen:

- schema v8 records `enemyCapacity: 64`, `encounterMaximumAlive: 4`, and the
  perceptive wizard profile;
- schema v7 reconstructs the historical four-entry enemy pool and exact
  omniscient `tactical-wizard-v1` behavior;
- schema v6 reconstructs the historical four-entry pool and
  `basic-wizard-v1` behavior;
- schema v2 through v5 remain pre-combat.

Enemy decisions remain autonomous fixed-step simulation, not synthetic input
commands. This release adds no sound, squad knowledge, networking, co-op actor,
friendly/critter perception, or lighting-driven detection.

## Geometry-only perception and facing

Every live v8 enemy owns an independent perception state:

`unaware → noticing → engaged → hunting → returning → unaware`

Dodge and low-health retreat are movement overlays and never erase this state
or its personal memory. A visual check succeeds only when the target center is
within `12m`, grid line of sight through walls and the obelisk is clear, and the
target is either inside the `120°` cone around authoritative facing or within
the `1.5m` 360-degree close-awareness radius. Rocks, lights, darkness,
TrueSight, particles, presentation height, and renderer state do not participate.

Checks run at `12Hz`, staggered over five deterministic lanes chosen from stable
enemy spawn sequence. First contact enters `noticing`; 15 uninterrupted fixed
ticks of qualifying samples confirm the player. Any failed noticing sample
resets the buildup. Hunting or returning enemies with existing visual memory
reacquire on their first successful sample. A mob with no confirmed target,
including one responding only to damage, must complete the normal buildup.

Facing is stored normalized and turns by at most `180°/s`. A visible target has
first priority, movement direction second, and state-specific scanning third.
Each guard stores its spawn position. Default-arena guards initially face away
from the obelisk; other scenarios choose one of eight deterministic headings.
Unaware guards sweep `±45°` around that heading on a six-second triangle wave
with an enemy-local phase. A guard displaced more than `0.5m` returns to post.

## Personal memory, search, and guard return

Every successful visual sample updates only that enemy's last-seen target
position, velocity, and tick. Losing sight immediately suppresses casting and
sends the enemy toward its personal last-seen point. Search begins within
`0.75m` of that point or after a 12-second travel timeout.

Search lasts exactly eight seconds. Candidate cells use reachable radii 1, 2,
and 3 in north, east, south, west, northeast, southeast, southwest, northwest
order, with a deterministic enemy-local rotation and reversal. The mob chooses
another candidate on arrival or after 90 ticks; when none is reachable it scans
in place. Search expiry starts guard return. Arrival clears perception memory
and returns the enemy to unaware. A map edit can disconnect a guard, but the
current reachable cell becomes the new guard only after the destination cache
has continuously proven the old guard unreachable for 12 seconds.

Unseen direct or splash damage starts or restarts an eight-second search around
the damage or impact point. The clue contains neither attacker identity nor the
player's hidden position, never shares between enemies, and cannot replace
existing visual memory.

## Tactical and combat interaction

Engaged enemies retain the 0.7.0 `6-9m` range control, deterministic strafe,
intercept aim, dodge, and health retreat. Casting requires `engaged`, no active
retreat, and a fresh same-tick cone/range/grid-line-of-sight check. A blocked
shot remains ready. Current authoritative player position and velocity are
used for aim only after that check; remembered coordinates are never fired on.
A same-tick Spell Lab Apply still precedes the autonomous cast, so the newly
applied projectile speed participates in intercept calculation immediately.

A hostile projectile is dodge-eligible only when it passes the frozen threat
calculation and is itself visible under the same cone, close-awareness, and
grid-occlusion rules. Seeing it reveals neither owner nor player and contributes
nothing to player exposure. Movement precedence is dodge, retreat, then
perception/tactical intent. Retreat uses the visible target field or latest
known hostile point while perception and search timers continue, and normal
behavior resumes at 60 health.

## Bounded data and 50-mob scaling

The live enemy typed-array pool has 64 entries while the authored encounter
still caps at four alive. Perception state/source, generic target identity,
samples, exposure, facing, guard, memory, hunt/search, stimulus, and navigation
identity are initialized, reset, and swap-moved with each stable actor. The
projectile pool increases from 128 to 256; particles remain 4,096 with bounded
drops for excessive Spell Lab effects. Legacy v6/v7 replay constructs its
historical four-enemy/128-projectile capacities.

The v7 player-rooted field remains frozen for legacy replay. Live v8 movement
uses a bounded destination cache with four pinned future actor-target slots and
64 shared goal-cell slots. One completed cost array belongs to each slot, while
all rebuilds share one preallocated Dijkstra builder and heap. Requests for the
same goal share a reference; referenced goals cannot be evicted. Stable slot
order and a global 2,048-expansion budget bound work each tick. Previous
completed data remains diagnostic while a target cell or map revision rebuilds,
but movement falls back to direct Plan-One wall sliding until the requested
field is current. Target approach descends target cost, withdrawal ascends
hostile cost, and hunt/return descends destination cost.

A preallocated map-cell broadphase replaces quadratic actor, rock, swept
projectile-hit, and dodge-candidate scans. Fixed typed candidate storage
deduplicates entries, then sorts them into the historical body-class and pool
index order before collision, contact, impulse, or first-hit resolution. Rocks
and actors remain local dynamic obstacles. Brute-force mode remains a test
oracle, not a second gameplay solver.

All scan, search, facing, strafe, and dodge decisions use named enemy-local hash
lanes. Global RNG, another enemy's cast sequence, particles, palette variation,
lighting, and TrueSight cannot perturb an existing mob's choices.

## Snapshots, diagnostics, and presentation

Each enemy snapshot and `window.__lantern.enemyDiagnostics(id?)` expose the
perception state/source, current visibility/sample/exposure, facing,
candidate/confirmed generic target identity, guard/base heading, personal
last-seen data, hunt anchor/search/timers/sequence, damage stimulus, and
destination-field slot/key/cost/version/stale/building state.

Global diagnostics report the bounded destination slots, active builder,
references, expansion budget, and map invalidation. A 128-entry event ring
retains detection, loss, search, return, damage-alert, reacquisition, and
awareness-clear events; the latest 32 plus retained/capacity/dropped telemetry
are copied to diagnostics.

AI View keeps its read-only Off/Selected/All semantics. Selected and All draw
the perception cone and close radius, facing/exposure, targets, memory or impact
clue, search goal, guard, and navigation state. Labels distinguish TrueSight's
**player sight** from authoritative **mob vision**. Ordinary Canvas2D and
Three.js hostile silhouettes share one procedural facing-marker footprint. It
shares hostile TrueSight concealment and adds no light; perception cones never
appear outside AI View. Before Three.js warmup the renderer preallocates 64
enemy instances, 64 markers, and 65 health tracks/fills. The separately logged
through-wall health-bar defect is unchanged.

## Automated verification

Coverage includes exact vision boundaries and buildup timing, occlusion and
non-occluding rocks, five-lane scheduling, turn/sweep limits, TrueSight
independence, hiding/reacquisition, personal memory, damage clues, visible-only
projectile dodge, exact search and return timeouts, guard rebasing, pool swaps,
tactical overlays, casting gates, current spell-speed Apply ordering, cache
sharing/invalidation/budgets/disconnected regions, broadphase/brute-force
equivalence, presentation parity, and exact schema-v8 and genuine v2-v7 replay
compatibility. The schema-v7 golden trace was captured from baseline commit
`2727c2e` and remains omniscient.

The perception soak runs 7,200 ticks with 50 living mobs, including 12 engaged
default casters and 38 guarding, hunting, or returning mobs. It exercises map
edits, damage alerts, dodge, retreat, deaths, and restarts while requiring
simulation p99 below 8 ms and heap growth below 64 MiB. A separate particles-off
50-caster case requires zero projectile drops with the default definition and
256-projectile pool.

Run:

```bash
npm run check
npm run test:soak
npm run test:soak:sight
npm run test:soak:spell
npm run test:soak:combat
npm run test:soak:ai
npm run test:soak:perception
git diff --check
```

The browser-only production-adapter fixture is available at
`test/browser/perception_stress.html?renderer=2d` from the development server.
It contains 12 engaged casters and 38 occluded searching guards without adding
a gameplay command or `window.__lantern` mutation API.

## Human release gate

Before the release commit, review Canvas2D, automatic Three.js, forced WebGL 2,
and a trusted-LAN phone. On the reference 1080p desktop with AI View Off,
simulation and presentation CPU p99 must each stay below 8 ms, median frame rate
must reach at least 55 FPS, and frame p95 must be no greater than 22 ms. Exercise
Selected mode separately; All mode has no performance guarantee. Confirm the
facing marker, TrueSight concealment, detection/hiding/search behavior, debug
labels, and resident resource identity. The release commit remains gated on
this behavioral and visual acceptance.
