# Lantern 0.9.1 Authoring and Vertical Traversal

> **Status:** current application checkpoint
>
> **Application/package:** `0.9.1` · **Snapshot/recording schema:** v12 · **Authoring map:** v5

Lantern 0.9.1 turns the former single-floor debug arena into a practical,
data-driven graybox sandbox without turning the engine into a general 3D
physics or ECS project. It preserves the 0.9.0 Fireball-investigation contract
and adds the authored world and limited vertical traversal needed to begin
building a small temple map.

## What is now current

- The saved source is a versioned `lantern-authoring-map` v5 document with
  stable IDs, named layers, signed base heights, surface and structure grids,
  sparse instances, player-start ownership, holes, and map-level connectors.
- The generated editor palette, deterministic picking, inspector, previews,
  semantic undo/redo, dirty state, validation, atomic load/import, and one
  optional reference layer all operate on authored source rather than runtime
  pools or renderer objects.
- Compilation is deterministic and per-layer. It derives compact collision and
  occlusion masks plus bounded runtime spawn recipes; runtime pushing, falling,
  elevator travel, and torch lights never rewrite authored starts.
- Eligible player, enemy, and dynamic clutter bodies have bounded world-Y,
  vertical velocity, support, and layer state. Floors and elevators are support
  providers, not passenger containers.
- A two-stop elevator follows an authored, unstoppable clock: default one-second
  dwell and two-second legs. It carries fitting riders without centering or
  locking X/Z, rejects oversized upper-frame loads deterministically, and keeps
  torch-light identity attached to its live body.
- Single-cell holes use the same positive-clearance aperture contract as upper
  elevator shafts. Fitting bodies receive rim attraction, can fall through
  multiple aligned floors, and can steer to land on an intermediate frame.
- `Space` starts one supported, committed player jump toward the world target.
  It can clear eligible low clutter and holes but has no double jump, variable
  height, or free jump steering. Pressure plates are visible authored instances
  and react only to eligible bodies genuinely supported on their floor.

## Compatibility boundary

Schema v12 records the committed jump command and current authoring-map
projection. Schema v11 and older recordings retain their frozen commands and
simulation branches. Authoring-map v4/v3/v2/v1 and legacy map/scenario imports
migrate explicitly to v5; successful saves emit v5. Scenario v3 remains the
compiled compatibility projection for recordings. Fireball definition v1 and
the 0.9.0 investigative-wizard behavior are unchanged.

## Test and explore

Run `npm run check` for the syntax and full Node test suite. Then start the
browser with `npm start -- --port 4174` if the default port is busy. Use
`?arena=holes&renderer=3d` for the integrated traversal playground: four floors,
staggered lifts, aligned holes, an intermediate landing, jump/plate fixtures, a
fitting torch or rock, and an oversized table.

Open the developer toolbox with `;`; `E` enters authoring, `Space` jumps, `P`
pauses, and `.` advances one fixed tick. Browser/GPU visual acceptance remains a
human check: verify deck/shaft visuals, floor handoff continuity, torch-light
continuity, controls, and the intended authored layout on the chosen renderer.

## Explicitly deferred

This checkpoint does not add a general 3D rigid-body system, arbitrary holes,
walking on clutter, fall damage, elevators called or navigated by AI, cross-layer
navigation/sight/sound/projectiles, doors, trap wiring, prefab rooms, persistent
history, autosave, map streaming, networking, final art, or authoritative
lighting.
