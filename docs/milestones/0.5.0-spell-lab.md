# Lantern 0.5.0 Spell Lab and Versioned Fireball Authoring

## Contract

Lantern 0.5.0 adds one reusable spell-authoring seam and one spell handler: Fireball. Spell Lab is a collapsible, non-modal overlay on desktop and a bottom drawer at `620px` and narrower. The rest of the arena remains interactive while the panel is open.

The registry owns stable spell code `1` for `fireball`, a player cooldown per spell code, an immutable revision map, and a monotonically increasing revision counter. A complete validated Apply creates the next revision. A cast captures spell code, definition revision, effect ID, and 32-bit effect seed. Every later authoritative or presentation decision for that effect resolves through those captured values.

The product intent is a developer tuning catalog first. Revisions are internal runtime identity that makes live tuning and replay safe; they are not a player-facing spell-history feature. Limited cosmetic customization could later reuse validated palette or presentation fields, but this release defines no player persistence, ownership, trading, loadout, or networking contract for customized spells.

This release does not add mana, loadouts, damage, sounds, more spells, pool-capacity authoring, fixed-tick authoring, collision-iteration authoring, or GPU-topology controls.

### Hard authoring limits

| Group | Limits |
| --- | --- |
| Cast | cooldown `0-5s` |
| Projectile | radius `0.02-1m`; speed `0.1-40m/s`; lifetime `0.1-20s`; spawn gap `0-1m` |
| Impact | blast radius `0-12m`; pressure impulse `0-5000`; visual life `0.02-2s` |
| Emission | integer burst `0-1024`; spawn height `0-2m`; gravity `-40-10m/s²`; horizontal speed, cap, bias, vertical minimum, and vertical range `0-30m/s`; vertical power `0-4` |
| Lifecycle | size `0.005-0.5m`; lifetime values `0.02-10s`; size scale `-10-10s`; shrink exponent `0-4` |
| Collision | retention `0-1`; ground mode `bounce-settle` or `remove`; wall collision boolean |
| Palette | exact `#RRGGBB`; gradient split `0-1`; hue variation `0-30°`; saturation/brightness variation `0-0.25` |
| Presentation | emissive `0-12`; light intensity `0-150`; range `0-20m`; decay `0-4` |

Validation additionally requires horizontal-speed minimum ≤ maximum, outward-bias minimum ≤ maximum, size minimum ≤ maximum, and lifetime minimum ≤ maximum. Values are rejected, never silently clamped.

## Distribution and lifecycle formulas

Each particle ordinal derives a sample seed from the effect seed. Named hash lanes make the dimensions independent:

```text
angle             = angle-lane × 2π
horizontal speed  = mix(speed minimum, speed maximum, speed-lane)
outward bias      = mix(bias minimum, bias maximum, bias-lane)
vertical velocity = vertical minimum + vertical range × vertical-lane ^ vertical power
size              = mix(size minimum, size maximum, size-lane)
normalized size   = (size - size minimum) / (size maximum - size minimum)
lifetime          = clamp(
  lifetime base
  + lifetime size scale × normalized size
  + (lifetime-lane - 0.5) × lifetime jitter,
  lifetime minimum,
  lifetime maximum
)
visible radius    = maximum size × remaining normalized life ^ shrink exponent
```

Angle, speed, bias, vertical velocity, lifetime, size, hue, saturation, and brightness are separate semantic lanes. Increasing the burst count cannot alter existing ordinals or the seed of a later successful cast. Palette-only variation cannot consume simulation RNG.

## Draft and cast workflow

- Numeric rows pair a slider and exact numeric input. Color rows pair a swatch and `#RRGGBB` field. Units and descriptor text are visible as labels/tooltips.
- Essentials opens initially. Projectile, Distribution, Lifetime, Collision, Palette, Emissive, and Lighting are independently collapsible.
- **Apply** validates a complete document against the displayed revision and creates an immutable revision for future casts.
- **Revert to applied** replaces the draft with the current applied document.
- **Reset draft to defaults** changes only the draft. It never applies automatically.
- **Copy JSON** and **Download JSON** operate only on a valid draft.
- **Import JSON** replaces the draft after parsing. Valid or invalid imported content remains unapplied until an explicit successful Apply.
- Simulation reset removes active effects and resets the successful-cast sequence while preserving applied revisions and the panel draft. The current applied documents become the new recording baseline.
- Browser reload returns to built-in defaults. Spell Lab does not use URL or local-storage persistence.

Normal LMB casts and **Recast last target** share one cast-command builder. Recast remains disabled until a target exists and while the normal Fireball cooldown is active. **Lock seed** makes both paths write the visible hexadecimal seed into the cast command. **New variation** creates and locks a new uint32 preview seed. Without a lock, a successful cast derives:

```text
hash32(simulation seed, spell code, successful-cast sequence)
```

Rejected casts do not advance the sequence. Successful automatic seeds are written explicitly into schema-v5 command history.

**Clear active effects** removes active Fireball projectiles, particles, retained visual impact events, and therefore their light leases. It does not reverse impulses already applied to the player or rocks.

## Authority boundary

Fixed-tick simulation owns projectile speed, radius, lifetime, and collision; blast radius and pressure impulse; emission distribution; particle gravity, lifecycle, ground response, and map/boundary collision. Those values always come from the revision captured by the cast.

Palette colors, emissive strengths, bloom response, point-light intensity/range/decay, mesh height, and shadows are presentation only. They cannot change collision, force, visibility, AI, command ordering, or replay truth. Debug Layers **Ground bounce** and **Spark walls** remain global test overrides around the captured per-spell collision behavior.

Canvas2D, Three.js instances, impact lights, and spark-carrier lights call the same allocation-free palette sampler. The existing `lightColorVariation` URL/probe key remains compatible and is labeled **Spell color variation**; it gates all geometry, particle, and light variation.

The Three.js path preallocates projectile and particle instance color/emissive attributes at full pool capacity before `compileAsync` warmup. Applying definitions writes resident attribute bytes only. Geometry, materials, TSL nodes, buffers, pipelines, and the resident eight-slot effect groups are not rebuilt. TrueSight continues masking meshes, emissive bloom, lights, and shadows before presentation.

## Commands, snapshots, and probes

The existing cast shape remains valid:

```js
{ cast: { x, z } }
{ cast: { x, z, spellId: "fireball", variationSeed: 0x12345678 } }
```

Omitted `spellId` means Fireball. New fixed-tick actions are:

```js
{ type: "applySpellDefinition", spellId, expectedRevision, definition }
{ type: "clearSpellEffects", spellId }
```

Snapshots use schema v5. Their compact `spells` table contains the current revision and only definitions referenced by live pools or retained events. Projectiles, particles, and events reference it with `spellCode` and `definitionRevision`; they also carry `effectId` and `effectSeed`. Particles add `sampleOrdinal` and `sampleSeed`. Swap removal copies every identity field.

The browser probe exposes:

```js
window.__lantern.listSpells()
window.__lantern.getSpellDefinition("fireball")
window.__lantern.applySpellDefinition("fireball", definition, expectedRevision)
window.__lantern.castSpell("fireball", x, z, { variationSeed })
window.__lantern.clearSpellEffects("fireball")
window.__lantern.spellDiagnostics("fireball")
```

Validation and malformed probe arguments return `{ ok: false, errors: [...] }` with paths and error codes. Diagnostics include current/applied revision, retained revisions, next automatic seed, cooldown, active counts, pool drops, latest impact, and sampled speed/lifetime/size/color ranges. Entity inspector records include spell, revision, effect ID, and seed.

## Recording compatibility

Schema-v5 recording configuration stores initial spell definitions and revision counters. Apply commands store deep-cloned complete documents. Replay restores the registry baseline, applies actions before casting in each tick, and reconstructs explicit seeds and effect-local samples exactly.

Schema-v2, v3, and v4 recordings use frozen legacy Fireball mechanics and global RNG consumption. They do not pass through the versioned handler. Schema v4 preserves its recorded particle profile and initial collision switches; schema v3 uses exact `m0.2`; schema v2 additionally disables spark-wall collision.

## Extension seam

A later spell adds one stable numeric registry code, one strict definition validator/descriptor set, and one named handler. Casting dispatches by handler after registry lookup; pools and events already carry generic spell/revision/effect identity. New handlers must preserve fixed-tick authority, explicit revision capture, bounded history, independent semantic randomness, structured validation, and presentation-only rendering fields.

## Validation

Automated acceptance covers strict validation and JSON round trips; future-casts-only revisions; impact, particle, collision, palette, and light capture; pool-swap identity; revision pruning; reset baselines; clear semantics; same-tick Apply-plus-cast ordering; pinned random fixtures and lane independence; schema-v5 exact replay plus schema-v2/v3/v4 fixtures; stable Three.js materials/nodes/attributes/lights; and maximum-definition/pool-saturation stress under the `8ms` simulation p99 target.
