# Lantern 0.9.0 Fireball Investigation AI

## Contract and release boundary

Lantern 0.9.0 advances the application/package/UI plus snapshot and
command-recording schema to v9 and makes `investigative-wizard-v1` the live
enemy profile. Scenario v3, map v1, Fireball definition v1,
performance-report v2, combat rules, pool capacities, and the default
four-alive encounter cadence remain unchanged.

Replay behavior remains selected by recording schema:

- schema v9 records `investigative-wizard-v1`, `enemyCapacity: 64`, and
  `encounterMaximumAlive: 4`;
- schema v8 reconstructs the frozen `perceptive-wizard-v1` schedule and
  behavior exactly;
- schemas v2 through v7 retain their existing legacy profiles and capacities.

This release adds authoritative enemy sensing, not player-facing audio.
Fireball explosions are its only audible stimulus. Footsteps, surface
acoustics, wall attenuation, squad knowledge, caster prediction, networking,
and a general sound-event framework remain deferred.

## Anonymous Fireball evidence

The v9 perception state appends `INVESTIGATING = 5`; `HUNTING` continues to
mean that a previously identified player disappeared. Knowledge sources append
`projectile = 3` and `sound = 4`, preserving every older numeric value.

During the existing staggered 12Hz sample, each enemy considers every visible
hostile Fireball within the existing 12m range, 120-degree cone or 1.5m close
radius, and grid line of sight. The nearest eligible projectile wins, with
ascending effect ID and projectile ID breaking equal-distance ties. A single
sample is sufficient: authoritative position, velocity, and age reconstruct
the launch point as `position - velocity × age`, clamped to a playable
map-cell center. The observation stores effect/projectile identity and pose for
diagnostics, but owner identity never identifies a caster or advances player
exposure.

Every hostile Fireball impact directly tests living enemy wizards within an
inclusive 16m radius. Hearing ignores walls, rocks, darkness, TrueSight, and
presentation state. Allied and neutral effects are ignored. The exact impact
point becomes the anchor, while the existing deterministic search pattern
supplies positional uncertainty. Impact processing follows that tick's AI
decision, so newly heard movement begins on the following tick.

## Priority and state arbitration

All v9 clue paths use one acceptance function. Priority is:

1. current direct sight of the player;
2. seen Fireball trajectory;
3. stored last-seen player position;
4. personal damage;
5. heard Fireball explosion.

Lower-priority evidence cannot redirect or restart stronger behavior. A newer
clue at the same priority redirects; clues received on the same tick use the
unsigned `(effectId, projectileId)` tuple as deterministic freshness. Repeated
samples of one projectile update its diagnostic observation without restarting
travel or search. Its later explosion is recognized as the same effect and
deduplicated before normal priority rejection.

Direct player sight always takes attention. A confirmed player is reacquired
on the first qualifying sample. Anonymous investigation retains the ordinary
15 uninterrupted exposure ticks for first identification; an interrupted
exposure resumes the retained investigation. Player last-seen coordinates may
replace the active anchor without erasing confirmed-target memory. Personal
damage enters `INVESTIGATING` and keeps its immediate local-search behavior.
Dodge and low-health retreat remain movement overrides and preserve the clue.

## Travel, search, and combat boundary

Investigation reuses the v8 navigation and search machinery. A wizard travels
until it reaches 0.75m from the anchor or the 720-tick travel timeout expires,
then searches reachable radius-1 through radius-3 cells for 480 ticks. A search
waypoint changes on arrival or after 90 ticks; the existing scan animation runs
when no waypoint is available. An unsuccessful search returns the wizard to
its guard position and clears the active clue on arrival.

`INVESTIGATING` never enables casting. A shot still requires `ENGAGED`, no
retreat, and a fresh same-tick player visibility check, so launch estimates,
impact points, damage points, and last-seen coordinates are never firing
targets.

## Bounded storage and scheduling

Each of the 64 enemy pool entries owns fixed-capacity investigation source,
priority, anchor, observation/acceptance ticks, effect/projectile IDs, observed
projectile pose/velocity/age, and inferred-origin fields. Spawn, reset, and
swap-move paths initialize and preserve them with the stable actor identity.

Schema v9 performs one map-cell broadphase rebuild before perception and
reuses that build for visual Fireball queries and dodge selection. The existing
post-movement rebuild remains the source for projectile collision and hearing
delivery. Schema-v8 scheduling is untouched. Navigation continues to use the
single preallocated destination-field builder and its global 2,048-expansion
per-tick cap.

## Diagnostics and AI View

Enemy snapshots and `window.__lantern.enemyDiagnostics(id?)` expose an
`investigation` object containing source, priority, anchor, observation and
acceptance ticks, effect/projectile IDs, observed projectile pose/velocity/age,
and inferred origin. `stimulus.position/tick` remains a compatibility view of
the active anchor. A bounded event ring and aggregate counters record
projectile observations, heard explosions, accepted redirects, deduplication,
and priority rejection.

AI View remains read-only. It gives `INVESTIGATING` a distinct color and adds a
sound-impact marker, the selected wizard's 16m hearing radius, projectile
observation point, reverse-trajectory ray, inferred-origin marker, and source,
priority, tick, effect ID, and projectile ID text. The shared overlay remains
presentation-only across Canvas2D and Three.js; TrueSight supplies no AI truth.

## Automated verification

Coverage exercises trajectory reconstruction and clamping, visibility and
team filtering, the inclusive hearing boundary, clue priority/freshness/ties,
same-effect deduplication, behind-wall sound, visible non-threatening
projectiles, trajectory-over-explosion behavior, redirects, last-seen/damage/
sound interactions, exposure and reacquisition, casting prohibition, dodge,
retreat, search/return timing, pool reset/swap, broadphase equivalence, v9
record/replay, and exact schema-v8 and older replay fixtures.

The 7,200-tick perception soak runs 50 living investigative wizards with visual
and auditory Fireball traffic while enforcing the existing p99, heap-growth,
and 2,048-expansion navigation limits. Run:

```bash
npm run check
npm run test:soak:perception
git diff --check
```

## Human release gate

In AI View, verify an occluded wizard hears a hostile explosion and searches
the impact area; a wizard seeing a projectile travels toward its inferred
launch point; that projectile's later explosion does not pull it from the
stronger clue; and travel, scanning, reacquisition, retreat/dodge recovery, and
guard return look natural. Repeat the behavior check in Canvas2D, automatic
Three.js, and forced WebGL 2. Browser/GPU visual acceptance remains separate
from automated simulation and replay evidence.
