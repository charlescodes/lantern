# Platform Contract

> **Current through:** Lantern 0.7.0

The engine is browser-first and built with standard JavaScript ES modules, HTML, and CSS. It targets modern desktop browsers, while Node.js is used only for development tooling, dependency management, testing, and the local development server. The core simulation should remain independent of the browser, renderer, and input devices so it can later run in a Web Worker, Node.js server, Electron application, or another host with minimal changes. The prototype runs entirely on the client, but the code preserves a clear boundary between commands, simulation state, and presentation so authoritative multiplayer can be added later without redesigning the engine.

Simulation truth remains a fixed 60 Hz X/Z world expressed in meters, seconds, and kilograms. Commands are consumed only at fixed-tick boundaries. The grid, actor collision, projectile collision, line-of-effect, health, enemy decisions, encounter cadence, and replay state belong to `src/sim`; Canvas2D, Three.js, DOM panels, height, emissive response, lights, and TrueSight concealment consume snapshots without simulation authority.

The current serialization boundary is snapshot/recording schema v7, scenario schema v3, map schema v1, Fireball definition format v1, and performance-report schema v2. Schema-v7 recordings name `obelisk-duel-v1` gameplay and `tactical-wizard-v1` enemy AI. Schema-v6 recordings select the frozen `basic-wizard-v1` direct-aim profile; schema v5 retains the versioned Fireball registry with frozen pre-combat behavior; schema-v2 through v4 retain their historical Fireball, particle, and collision profiles. Legacy scenario v2 and map v1 imports have no obelisk and therefore no encounter.

The default scenario owns exactly one invulnerable obelisk. Its solid cell is ordinary simulation occlusion for actors, projectiles, blast rays, AI line-of-sight, and TrueSight, while renderers replace that wall cell with procedural obelisk geometry. Enemy wizards live in a four-entry typed-array pool and use deterministic autonomous simulation, never synthetic player commands. One simulation-authoritative, preallocated navigation field is shared by all tactical enemies and incrementally rebuilds after player-cell or map-revision changes. Player and enemy casts resolve through the same versioned Fireball registry, but each caster owns independent cooldown and successful-cast sequence state.

Tactical choices are isolated from global simulation RNG and presentation state. Stable enemy spawn sequence and named hash lanes drive strafe side/timing and dodge ties. Navigation ignores dynamic rocks and actors, which remain local collision obstacles. Intercept aim consumes current authoritative player velocity and the applied Fireball speed; hostile-projectile threat detection, dodge timers, retreat hysteresis, and casting suppression all execute inside the fixed tick. TrueSight supplies no AI knowledge.

Combat health is symmetric and fixed outside Fireball definition v1: actors have 100 maximum health, direct opponent hits deal 25, and splash damage uses the captured blast radius with linear surface-distance falloff. Team immunity affects health and projectile actor collision only; physical explosion impulse remains neutral. Defeat freezes autonomous gameplay for 90 fixed ticks while reset and Spell Lab actions remain authoritative, then rebuilds the same-seed encounter baseline while preserving the applied spell revision and panel draft.

Presentation must keep Canvas2D and Three.js behavior aligned from the same snapshot data. The Three.js adapter preallocates four enemy instances and five health-track/fill instances before warmup. Health tracks and fills share the transparent render queue, with the fill ordered after the track, so the color remains visible during ordinary rendering and TrueSight fades. Combat adds no external art, lights, or dynamic-light topology. TrueSight hides an enemy, its health bar, and every hostile effect carrier together, but never changes AI knowledge or replay truth. The optional AI View is a shared read-only Canvas2D diagnostic overlay above either renderer; its Off/Selected/All modes and stable mob selection do not inject commands or change replay state. Unlike ordinary actor presentation, its clearly labeled diagnostics intentionally remain visible through TrueSight for developer inspection.
