# Platform Contract

> **Current through:** Lantern 0.9.3, authoring-map v8, and snapshot/recording schema v24

Schema v24 adds `authored-mechanisms-v1` with pinned graph/device limits and
the edge-triggered `interact: true` command. Authoring-map v8 adds a declarative
`mechanisms` graph; v7 migrates by adding an empty graph. Sources and stateful
outputs cross fixed-tick registers, combinational logic evaluates in stable
order, and gate requests run before motion. Runtime gate overlays drive
collision, navigation invalidation, and TrueSight without editing source cells.
Schemas v2–v23 force mechanisms off. See the
[mechanism contract](./notes/authored-mechanisms.md) for exact timing, controls,
editor workflow, diagnostics, and the remaining manual acceptance gate.

The engine is browser-first and built with standard JavaScript ES modules, HTML, and CSS. It targets modern desktop browsers, while Node.js is used only for development tooling, dependency management, testing, and the local development server. The core simulation should remain independent of the browser, renderer, and input devices so it can later run in a Web Worker, Node.js server, Electron application, or another host with minimal changes. The prototype runs entirely on the client, but the code preserves a clear boundary between commands, simulation state, and presentation so authoritative multiplayer can be added later without redesigning the engine.

Simulation truth remains a fixed 60 Hz world expressed in meters, seconds, and kilograms. X/Z collision remains deliberately 2D, while eligible bodies also own bounded authoritative world Y, vertical velocity, support, and layer state for floors, holes, jumps, and elevators. Commands are consumed only at fixed-tick boundaries. The grid, actor collision, projectile collision, line-of-effect, health, enemy decisions, encounter cadence, authoring compilation, vertical supports, and replay state belong to `src/sim`; Canvas2D, Three.js, DOM panels, emissive response, lights, and TrueSight concealment consume snapshots without simulation authority.

The current serialization boundary is snapshot/recording schema v24, authoring-map v8, scenario schema v3, map schema v1, Fireball definition format v1, and performance-report schema v4. Schema v23 records `destructible-obelisks-v1`: each obelisk starts with 600 non-regenerating health, receives opposing combat damage, emits bounded damage/death events, disables its encounter at zero, and removes its disposable runtime collision/occlusion cell until reset. Schema v22 and earlier force this profile off and preserve invulnerable obelisks. Schema v22 records `banked-sentry-obelisk-encounters-v3`: an ineligible obelisk retains at most one due spawn, releases one enemy immediately when the same-floor player is both within 20 meters and visible, and schedules subsequent attempts from that release tick until reaching its authored living cap. Schema v21 preserves `sentry-obelisk-encounters-v2`, including its historical overdue catch-up cadence and the same range/visibility gate; wizard and urchin starting actors may also be authored independently of obelisks. Schema v20 preserves `independent-obelisk-encounters-v1`: every authored obelisk owns a bounded schedule, enemy archetype, living cap up to 4, and spawn cadence while all encounters share the 64-enemy global pool. New authored obelisks default to urchins with a living cap of 4. Authoring-map v7 represents obelisks as ordinary stable, floor-owned instances and migrates the former v6 singleton marker without changing historical recordings. Schema v19 records `floor-aware-enemy-home-v1`: spawned enemies retain the stable obelisk identity, floor, and position they were assigned at birth, return through authored cross-floor routes, and wait and retry when home is unreachable. Schema v18 records `projectile-height-collision-v1`: projectiles retain authoritative caster-relative world Y, pass over low tables and small/medium rocks, and collide with tall props or elevator volumes only when their swept vertical intervals overlap; actor and corpse contacts remain layer-local. Schemas v2-v17 force this profile off and preserve their historical two-dimensional projectile contacts. Schema v17 records `observed-hole-pursuit-v1`: an enemy with direct visual evidence of a player entering a live floor aperture may route locally into that opening, fall through the ordinary vertical solver, and search from its own landing point. Schemas v2-v16 force this profile off. Schema v16 records `enemy-archetypes-v1`; schema v15 records `authored-navigation-topology-v1` plus bounded topology capacities, authored patrol, and observed elevator pursuit; schemas v2-v14 select topology profile `none`. Authoring-map v6 added stable navigation nodes, undirected same-floor links, and connector endpoint references while preserving exact migrated v5 connector coordinates. Schema v14 records `breakaway-floor-v1`, a latched 18-tick floor-to-hole profile that reuses ordinary aperture/falling rules; schemas v2-v13 force it off. Schema v13 records `elevator-projectile-collision-v1`, so Fireballs impact a stopped elevator deck or the lower-floor shaft/piston while preserving schema-v12's pre-elevator behavior. Schema v12 records the committed player-jump edge and a current authoring-map projection while preserving v2-v11 behavior. Authoring-map v7 retains stable named layers, per-layer terrain/instances, player-start ownership, holes, breakaway surfaces, map-level autonomous two-stop connectors, navigation topology, and authored enemy starts; runtime movement never writes authored starts or obelisks back. Legacy scenario v2 and map v1 imports have no obelisk and therefore no encounter.

The default scenario owns exactly one destructible obelisk. While alive, its solid cell is ordinary simulation occlusion for actors, projectiles, blast rays, AI line-of-sight, and TrueSight. At zero health its encounter stops, the runtime cell becomes open, and renderers retain non-colliding rubble; reset reconstructs the authored pristine state. Existing spawned enemies keep their captured home identity. Live enemies occupy a 64-entry typed-array pool, while each authored obelisk caps at four living children by default. Enemy death transfers into a 16-entry dynamic SoA body pool and then a 100-entry inert FIFO ring; supported replay-pinned ceilings are 64 and 1,000. Player and enemy casts resolve through the same versioned Fireball registry, but each caster owns independent cooldown and successful-cast sequence state. The default projectile pool is 256, the one-tick sound queue is 257, and the particle pool remains 4,096, all with bounded drop behavior.

RMB movement begins walking when its first held world target is inside the inclusive `0.75m` radius (`1.5m` diameter) around the live player center and begins running when farther away. From a centered one-meter cell, the circle reaches into all eight neighboring cells. A walking gesture promotes immediately when its live target exceeds that radius; running remains latched even if the target returns inside and clears only when RMB is released. Walking uses `2.25m/s`; running requests `4.5m/s` through the existing locomotion acceleration. Walking, release braking, and external knockback are silent. Running emits at most one anonymous footstep per tick: after `0.75m` on entry, every `1.5m` thereafter, or on a heading change of at least 120 degrees behind a 12-tick gate. Release resets cadence. Schemas v2-v10 retain full-speed nonzero movement and emit no footsteps.

Live visual perception is geometry-only simulation authority. A qualifying player or hostile-Fireball sample requires the center within 12m, clear grid line-of-sight, and either a 120-degree cone around normalized authoritative facing or the 1.5m 360-degree close radius. Walls and the obelisk occlude. Rocks, darkness, lights, TrueSight, particles, renderer state, and presentation height do not. Samples run at 12Hz across five deterministic spawn-sequence lanes; 15 uninterrupted ticks of qualifying player samples confirm the player, while one visible Fireball sample is sufficient because projectile position, velocity, and age are authoritative. Projectile owner identity is never used for exposure or caster identification. Facing turns at no more than 180 degrees per second. Unaware guards store their spawn point and sweep 45 degrees to either side of their base heading over a six-second local-phase cycle.

Confirmed target knowledge and investigation clues are personal. Each mob records last-seen position, velocity, and tick; losing sight stops casting, travels to that point, searches reachable radius-1 through radius-3 cells for exactly eight seconds, then returns to guard and clears memory. A completed destination field must prove a guard unreachable continuously for 12 seconds before the current reachable cell becomes the new guard. A visible hostile Fireball infers its clamped launch point as `position - velocity × age`. Living hostile wizards hear an exact player-footstep origin within an inclusive 8m and a hostile Fireball impact within an inclusive 16m regardless of walls, rocks, darkness, or TrueSight. Unseen damage records only its impact point and starts an immediate local search. Evidence is accepted centrally in descending priority: current direct player sight, visible Fireball trajectory, stored last-seen player position, personal damage, then sound. Newer equal-priority sound IDs redirect; repeated samples and the same Fireball effect's later explosion are deduplicated. Anonymous evidence never identifies a player or caster, advances exposure, or permits firing. The one-tick typed sound queue delivers in stable insertion order and drops newest on overflow; its separate diagnostic ring cannot affect AI. This release has one generic actor target, the player; enemy footsteps, player-facing audio, surface acoustics, wall attenuation, squad sharing, co-op selection, networking, and friendly/critter perception remain outside the authority boundary.

The destination cache owns four pinned actor-target slots and 64 shared goal-cell slots. Every slot retains one completed cost array, while builds serialize through one preallocated Dijkstra workspace in stable slot order under a single 2,048-expansion tick budget. A previous completed array remains available while its replacement builds, but movers use direct wall-sliding until the requested field is current. Approach follows decreasing target cost; withdrawal follows increasing hostile cost; hunt/investigation/search/return follow decreasing goal cost. A preallocated map-cell broadphase supplies deterministic actor, rock, dynamic-body, swept-projectile, visual-projectile, dodge, and hearing candidates in historical body-class and pool-index order. Schema v11 preserves the schema-v10 destination, physics, body, and perception schedules while routing Fireball hearing and new footsteps through the sound queue after enemy movement. Schema-v8 scheduling is unchanged. Dynamic rocks, bodies, and actors remain local obstacles rather than navigation-field inputs.

Tactical choices remain isolated from global simulation RNG and presentation state. Stable enemy spawn sequence and named hash lanes drive guard headings/phases, search transforms/scans, strafe side/timing, and dodge ties. While engaged, v11 retains the schema-v9 range control, strafe, intercept, visible-projectile dodge, and health retreat. Casting requires engaged state, no retreat, and a fresh same-tick cone/range/grid-LOS check; remembered, inferred, or heard coordinates are never firing targets. Dodge and retreat override movement without clearing perception or investigation state or pausing hunt/search clocks. TrueSight supplies no AI knowledge.

Combat health is symmetric and fixed outside Fireball definition v1: actors have 100 maximum health, direct opponent hits deal 25, and splash damage uses the captured blast radius with linear surface-distance falloff. Team immunity affects living-actor health and projectile collision only; physical explosion impulse remains neutral. Dynamic dead bodies intercept either team's Fireball and receive only grid-occluded impulse. They retain the enemy's `0.3m`, `75kg` centered X/Z circle, interact with actors, rocks, bodies, and the map, and settle after a 36-tick fall plus 30 uninterrupted quiet ticks or at a hard 180-tick age. Capacity pressure settles the oldest dynamic body. Inert FIFO entries have no simulation interactions or per-tick work. Defeat freezes autonomous gameplay for 90 fixed ticks while reset and Spell Lab actions remain authoritative, then rebuilds the same-seed encounter baseline while preserving the applied spell revision and panel draft.

Presentation must keep Canvas2D and Three.js behavior aligned from the same snapshot data. The Three.js adapter preallocates 64 enemy instances, 64 facing markers, 64 pristine/rubble obelisk groups, 129 health-track/fill instances, and one resident dead-body instance pool at the replay-pinned combined capacity before warmup. The procedural front marker derives from the same normalized facing snapshot in both renderers. Dead bodies instead share a dark material and one renderer-independent pose: tilt 90 degrees toward last facing over 36 ticks, lower the cylinder center from `Y=0.8m` to its radius, preserve X/Z, and render the equivalent Canvas capsule. Bodies share TrueSight concealment and add no health bar, marker, or light. Health tracks and fills retain their established transparent render ordering; the separately recorded through-wall health-bar defect remains open. TrueSight never changes AI knowledge or replay truth. AI View remains a shared read-only overlay: Off/Selected/All semantics and stable selection do not inject commands, and its clearly labeled mob-vision diagnostics intentionally remain visible through TrueSight for developer inspection.

The ordinary browser route boots into full-viewport play mode. One local semicolon gate owns the top controls, authoring windows, instrumentation, coordinate/help chrome, inspection, AI View drawing, and presentation diagnostics. Closing that gate never changes snapshot, command, replay, or recorded particle-collision configuration; it only suppresses developer presentation and disables developer keyboard shortcuts. Spell Lab starts parked behind its toolbox launcher, and collapsing it removes the panel from the arena while retaining its local draft state.

In play mode, both presentation cameras focus every rendered frame on the same locally interpolated X/Z pose used to draw the player. There is no spring, dead zone, prediction, or network buffering. A stationary viewport pointer is reprojected after camera movement so movement targets, casts, cursor markers, and inspection stay aligned. Wheel zoom preserves the player-centered target and MMB cannot detach the play camera. Edit mode inherits the last play view, then retains cursor-anchored zoom, world-meter MMB panning, and explicit Focus/F recentering until it returns to play.
